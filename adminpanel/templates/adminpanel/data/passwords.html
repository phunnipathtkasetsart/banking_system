How passwords are stored

DigiBank never stores a password. It stores a one-way hash made by Django's PBKDF2-SHA256 hasher. At login, Django hashes what was typed with the same salt and iteration count, then compares the two hashes.

Anatomy of a stored value

{% if u.parts.algorithm %}{{ u.parts.algorithm }}${{ u.parts.iterations }}${{ u.parts.salt }}${{ u.parts.hash }}{% else %}{{ u.parts.raw }}{% endif %}

{% endwith %}
algorithm
pbkdf2_sha256: PBKDF2 key stretching with HMAC-SHA256 (Django's default hasher).
iterations
How many times SHA-256 is applied in a row. A high count makes each guess slow for an attacker, but one login stays fast.
salt
Random text created per password. Two people with the same password still get different hashes, so precomputed lookup tables don't work.
hash
The 32-byte derived key, base64-encoded. It can't be reversed back into the password.
